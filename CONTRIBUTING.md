# Contributing to H-Toolbelt

Thanks for your interest in improving H-Toolbelt. This document describes the
basic workflow for contributions.

## Issues

- Search existing issues before opening a new one.
- For bug reports, include your After Effects version, OS, and clear steps to
  reproduce.
- For feature requests, describe the motion-design workflow you want to speed up.

## Pull requests

1. Fork the repository and create a topic branch off `main`.
2. Make focused changes; keep unrelated edits in separate PRs.
3. Ensure the project still checks out, builds and packages:
   ```bash
   yarn install
   yarn test          # unit tests for the pure shared modules
   yarn typecheck     # ExtendScript host + Svelte UI (including the evalTS bridge)
   yarn smoke         # debug build + bundle symbol check + host ES3 check
   yarn build         # release build (minified)
   yarn zxp           # signed package
   ```
   This is the same order the release workflow runs, and the order matters:
   `build`, `build:debug` and `zxp` each start with `rimraf dist/*`, so anything
   that inspects `dist/` has to run before the build that replaces it.
4. Open a pull request describing the change and how you verified it.

## Debugging the panel

For a live, readable development build with hot-module reload and sourcemaps
(non-minified), run:

```bash
yarn dev
```

This serves the panel over Vite (HMR) instead of the packaged bundle. With CEP
`PlayerDebugMode` enabled, open the panel in After Effects
(**Window → Extensions → H-Toolbelt**) and attach Chrome to the CEP remote
debugger at the port listed in `dist/cep/.debug` (currently
`http://localhost:8860` for AEFT) to inspect the console, network, and readable
stack traces.

For a one-off readable build without the dev server, use `yarn build:debug`,
which disables minification and emits sourcemaps. `yarn build` is the release
build and minifies.

### Why `yarn smoke` builds its own bundle

`scripts/smoke-bundle.mjs` proves that every symbol the UI imports has a real
*binding* in the bundle — the failure mode behind the P02a/P02b blank panel,
where `svelte-preprocess` dropped an import used only in a template and the panel
threw `ReferenceError` on mount. Searching for the bare name is not enough: the
compiled call site `CurveEditor(node, {...})` survives even when the definition
does not, so the check looks for `function|const|let|var|class NAME`.

Minification renames exactly those bindings, so the check cannot run against a
release build without being weakened into uselessness. `yarn smoke` therefore
runs `yarn build:debug` itself before checking, which also makes it impossible to
accidentally validate a stale or minified `dist/`.

### The host ES3 check

`yarn check:es3` (also part of `yarn smoke`) parses the built ExtendScript bundle
and walks its AST looking for ES5+ builtins. Modern *syntax* would fail to parse
inside After Effects and break loudly; modern *builtins* are the quiet failure —
`Math.imul` parses fine and throws only when a user clicks the button, in a code
path Node unit tests cannot catch because Node has `Math.imul`.

It parses rather than greps because the host legitimately contains strings like
`Math.abs(...)` — that is After Effects *expression text* generated by
`shared/expressions`, data here and a program only inside AE — and because doc
comments discuss these functions by name. If you add a construct the guard
rejects but that ExtendScript genuinely supports, add it to the `AMBIGUOUS` lists
with a comment explaining why, rather than deleting the rule.

## Commit messages

This project uses [Conventional Commits](https://www.conventionalcommits.org/).
Use prefixes such as `feat:`, `fix:`, `chore:`, `ci:`, and `docs:`.

## Language

All code, comments, documentation, filenames, and commit messages are written in
**English**.
